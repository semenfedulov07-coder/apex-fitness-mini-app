# APEX — Performance

Готовая портфолио-демонстрация фитнес-платформы вымышленного тренера Марка Волкова: клиентская Mini App и отдельный кабинет тренера. Язык — русский. Фотографии сгенерированы специально для проекта; отзывы, истории результатов и биография вымышлены.

## Быстро посмотреть

Открой опубликованную версию в браузере. На главной нажми **Выбрать программу → MASS 90 → Выбрать тариф → Получить демо-доступ**. Деньги не списываются. В кабинете выбери день тренировки, отметь упражнения и заверши занятие. Затем открой **Прогресс**.

Админ-панель находится по адресу **/admin**. Также есть ссылка **Кабинет тренера** внизу приложения и в профиле. Пароль для демонстрации не нужен.

Изменения сохраняются только в текущем браузере. Другой телефон и другой браузер имеют собственные данные. Приватная опубликованная версия доступна владельцу; для открытия клиентам или через Telegram потребуется отдельно подготовить доступный им HTTPS-адрес.

## Запуск на своём компьютере

1. Установи Node.js версии 22.13 или новее. Перезапусти терминал после установки.
2. Распакуй проект в отдельную папку.
3. Открой терминал в этой папке: в Windows можно в адресной строке Проводника написать `cmd` и нажать Enter.
4. Выполни команды по очереди:

```bash
npm install --global pnpm@11.25.0
pnpm install
pnpm dev
```

5. Открой **http://localhost:5173**. Админ-панель: **http://localhost:5173/admin**.
6. Пока идёт локальная демонстрация, оставляй терминал открытым. Остановка: Ctrl+C. Повторный запуск: `pnpm dev`.

Токен бота, база данных и платёжные ключи для демо не нужны. Установка зависимостей требует интернета. Если pnpm сообщает о несовместимой версии Node, обнови Node до поддерживаемой им LTS-версии.

## Проверка и сборка

```bash
pnpm exec tsc --noEmit
pnpm build
```

Проект использует React 19, TypeScript, Vite/Vinext, CSS, Radix/Shadcn для доступных интерактивных компонентов, Lucide для иконок и Sonner для уведомлений. Vinext сохраняет файловые маршруты `/` и `/admin`. В рабочей среде Sites применяется её настроенная сборка, локально скрипты автоматически выбирают переносимый режим. Локальная команда запуска готовой сборки: `pnpm exec vinext start`. Для обычного редактирования достаточно `pnpm dev`.

## Что работает

- Четыре программы: MASS 90, LEAN 60, HOME 30, ATHLETE 90, подробные страницы, три тарифа на программу.
- Демо-покупка, личный кабинет, история покупок, переключение приобретённых программ.
- Недельный план, переключение недель кнопками и свайпом, разминка, упражнения, отметки, таймер отдыха, завершение занятия.
- По 10 уроков на программу. Демонстрационный плеер и поддержка реального MP4.
- Привычки по датам, текущая серия активности, статистика тренировок, график веса и добавление веса.
- Пример питания и форма заявки на персональное сопровождение.
- Demo CMS: создание/изменение/удаление программ, уроков, отзывов, результатов, медиа; изменение порядка уроков, цен и профиля тренера; просмотр заявок.
- Фото по URL, выбор из медиатеки и локальные изображения до 1,5 МБ.
- Поддержка имени/аватара Telegram при наличии, BackButton, haptic, safe areas и viewport. В обычном браузере — самостоятельная рабочая версия.
- Синхронизация изменений между вкладками одного браузера через событие storage.

## Что демонстрационное

Оплата, пользователи администратора и его график активности, консультации, напоминания, рекомендации питания, отзывы, история веса до пользовательских записей и все transformation cases — демо. Начальная заявка Анны также вымышлена. Реальные сообщения и push не отправляются. Видео изначально не добавлены.

Серия активности считается по дням с отмеченными привычками; завершение тренировки автоматически отмечает привычку «Тренировка». Повторное завершение того же занятия не увеличивает счётчик. Процент программы считается по завершённым занятиям. Стартовые точки веса — примеры; новые значения добавляются по датам. План начинается с текущей недели и хранит прогресс по номеру недели программы, а не по серверному календарю. HOME 30 использует четыре недельных блока. Для новой программы CMS использует готовые шаблоны тренировок; редактирование упражнений пока находится в слое данных.

Удалённая программа исчезает из каталога, её уроки удаляются. Запись о покупке остаётся как архивная. Черновик не появляется в каталоге; у ранее купленной программы доступ сохраняется. Видео из черновиков не включаются в библиотеку.

Чтобы вернуть исходное состояние: **Профиль → Сбросить демо-данные → Сбросить данные**. Это также удалит изменения CMS.

## Где менять данные и код

- `lib/apex/models.ts` — модели программ, уроков, покупок и других сущностей.
- `lib/apex/data.ts` — начальные данные, упражнения, пакеты и FAQ.
- `lib/apex/store.ts` — интерфейс Repository и реализация в localStorage.
- `lib/apex/telegram.ts` — адаптер Telegram и браузерный fallback.
- `lib/apex/webmcp.ts` — необязательные браузерные инструменты просмотра/открытия программ.
- `components/apex/app.tsx` — клиентские экраны и пользовательские действия.
- `components/apex/admin.tsx` — кабинет тренера.
- `components/apex/ui.tsx` — повторно используемые элементы.
- `app/globals.css` — дизайн, адаптивность, reduced-motion.
- `public/images/` — локальные оптимизированные фотографии.

Изменение начальных данных не перезаписывает сохранённую демо-сессию: после правки seed-данных сбрось демо через профиль. Не сохраняй секреты в клиентских файлах или в localStorage.

## Как добавить настоящее видео без изменения кода

1. Открой `/admin` → **Уроки и видео**.
2. Выбери программу → **Добавить урок** или карандаш у существующего.
3. Заполни название, описание и длительность. Выбери обложку из медиатеки.
4. Вставь **прямую HTTPS-ссылку на MP4** в поле «Ссылка на видео».
5. Выбери «Опубликован» → **Сохранить изменения**.
6. В клиентской части открой купленную программу → библиотеку → урок.

`videoUrl` хранит адрес медиафайла. Пустое значение показывает демо-обложку. Заполненное значение подключается к HTML5 `<video controls playsInline>`. Ссылка на страницу YouTube не является прямым MP4. HLS, закрытый видеохостинг, подписанные ссылки и адаптивное качество потребуют отдельного адаптера плеера. Хостинг видео должен разрешать загрузку в браузере; в реальном продукте доступ выдаётся сервером.

## Будущий backend

1. Создать серверные таблицы users, programs, lessons, purchases, workout_logs, habits, weights, applications и media. Сохранить текущие модели как контракты API.
2. Заменить localRepository на асинхронный API-адаптер, добавить серверную загрузку и состояния ошибок. UI и модели можно сохранить; hook состояния нужно адаптировать к асинхронным операциям.
3. Отправлять Telegram `initData` на сервер и проверять подпись и время. `initDataUnsafe` используется здесь только для отображения имени; доверять ему для доступа нельзя.
4. Добавить настоящую авторизацию тренера, роли и серверные правила доступа. `/admin` в этой версии не защищён.
5. Фотографии перенести в Storage, видео — в подходящий видеохостинг, заявки и прогресс — в базу. Для уведомлений нужен отдельный серверный процесс.
6. Заменить локальную демо-покупку на проверенный серверный платёжный сценарий. Доступ выдавать только после подтверждённого webhook, с защитой от повторной обработки. Для цифровых товаров внутри Telegram учитывать требования Telegram Stars.

## Подключение к Telegram-боту

1. Подготовить HTTPS-адрес, доступный будущим клиентам, и проверить его в мобильном браузере. Приватный адрес с входом владельца не подходит для широкой клиентской Mini App.
2. Открыть своего бота в **@BotFather → /mybots → Bot Settings → Menu Button** и указать HTTPS-адрес и название кнопки. Альтернатива — Main Mini App в настройках бота.
3. Открыть кнопку бота в Telegram и проверить имя, аватар, навигацию и safe areas на iOS/Android.
4. Для реальных аккаунтов и платежей выполнить backend-шаги выше. Bot Token хранить только на сервере в переменных окружения.

Официальная документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [платежи за цифровые товары](https://core.telegram.org/bots/payments-stars).
